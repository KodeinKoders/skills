= Antora component templates
:icons: font

Copy-paste templates for the component described in `SKILL.md`.
Replace `Lib`, `lib` and the coordinates with the library's own.


== Creating a component

1. Write `doc/antora.yml` from the template below, with the release version of the root `build.gradle.kts`.
2. Create `modules/ROOT` with its nav, `index.adoc` and `getting-started.adoc`.
3. Create `modules/core`, starting with `setup.adoc`, then one page per concept.
4. Add a module per family of context pages (`guides`, `framework`...), and `migration` when there is a previous major version.
5. List every module nav in `antora.yml`.


== `antora.yml`

For release `1.3.0`:

[source,yaml]
----
name: lib
title: Lib
version: '1.3.0' # <1>
display_version: '1.3' # <2>
nav:
  - modules/ROOT/nav.adoc
  - modules/core/nav.adoc
  - modules/guides/nav.adoc
  - modules/migration/nav.adoc
asciidoc:
  attributes:
    version: '1.3.0' # <3>
    kotlin-version: '2.4.20' # <4>
    ksp-version: '2.3.12'
    jdk: '17' # <5>
----
<1> The release version, `1.3.0-RC1` for a pre-release.
<2> The version without patch or tag, quoted so that YAML does not read `1.10` as `1.1`.
<3> The release version again, which pages write `\{version}`.
<4> Equal to the `kotlin` version of `gradle/libs.versions.toml`, like every `XXX-version` attribute.
<5> Not in the version catalog, so its name does not end in `-version`.


== Standalone site

A library that publishes its own site keeps its component in `docs/` instead of `doc/`, and adds the files below at the repository root.
Replace `Lib`, `lib` and the GitHub coordinates with the library's own.

.`antora-playbook.yml`
[source,yaml]
----
site:
  title: Lib Documentation
  url: https://KodeinKoders.github.io/Lib # <1>
  start_page: lib::index.adoc # <2>
  robots: allow
content:
  sources:
    - url: ./ # <3>
      start_path: docs
asciidoc:
  extensions:
    - '@asciidoctor/tabs' # <4>
ui:
  bundle:
    url: https://github.com/kosi-libs/documentation-ui/raw/cup/build/ui-bundle-v1.2.2.zip # <5>
  supplemental_files:
    - path: ui.yml
      contents: |
        static_files: [ .nojekyll ]
    - path: .nojekyll # <6>
urls:
  redirect_facility: 'static'
output:
  dir: build/site
----
<1> Where GitHub Pages serves the site.
<2> `name` of the component from `antora.yml`, then `::` and the page.
<3> The repository itself, so the site is built from the checked-out branch.
<4> Only if the pages use tabs; the package must then be in `package.json`.
<5> The UI bundle that the site is themed with.
<6> Without an empty `.nojekyll`, GitHub Pages ignores the directories whose name starts with an underscore, which Antora's assets do.

.`package.json`
[source,json]
----
{
  "dependencies": {
    "antora": "^3.1.7",
    "@asciidoctor/tabs": "^1.0.0-beta.6"
  }
}
----

Build it with `npm install` then `npx antora antora-playbook.yml`; the site lands in `build/site`.
Add `node_modules` and `build` to `.gitignore`.
A GitHub Actions workflow runs the same two commands and publishes `build/site` to GitHub Pages.

[source,kotlin,subs="verbatim,attributes"]

    kotlin("multiplatform")
    id("org.kodein.lib") version "{version}" // <1>
}
------
